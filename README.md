# Вместе — комната для двоих

Статический сайт: комната с паролем, чат и показ экрана (любое окно, вкладка или весь рабочий стол) прямо в браузере. Ничего устанавливать не нужно, сервер не требуется — только GitHub Pages и браузеры.

## Что внутри

| Файл | Зачем |
| --- | --- |
| `index.html` | Вся разметка: лобби (создать комнату / войти) и комната (экран + чат) |
| `styles.css` | Оформление и адаптив под телефон |
| `app.js` | Логика: пароль → адрес комнаты, чат, WebRTC-соединение, показ экрана, микрофон, микшер громкости |

Сторонняя зависимость одна — библиотека [PeerJS](https://peerjs.com) (обмен служебными сообщениями при установке соединения). Она подгружается с CDN при входе в комнату.

## Как выложить на GitHub Pages

1. Создайте на GitHub пустой **публичный** репозиторий, например `vmeste` (на бесплатном плане Pages работает только в публичных репозиториях).
2. Загрузите в корень репозитория три файла: `index.html`, `styles.css`, `app.js` (кнопка **Add file → Upload files** → Commit).
3. Откройте **Settings → Pages**. В блоке *Build and deployment*: Source — **Deploy from a branch**, Branch — **main**, папка — **/ (root)**, затем **Save**.
4. Через минуту-две сайт будет доступен по адресу `https://<ваш-логин>.github.io/vmeste/`.

Адрес обязательно должен начинаться с `https://` — иначе браузер не даст ни показать экран, ни создать комнату (это защита самого браузера, обойти её нельзя).

Если работаете через git:

```bash
git init
git add index.html styles.css app.js README.md .gitignore
git commit -m "Комната для двоих: чат и показ экрана"
git branch -M main
git remote add origin https://github.com/<логин>/vmeste.git
git push -u origin main
```

## Как пользоваться

**Вы (с компьютера):** «Создать комнату» → название (например, `вечер-сериал`), пароль и имя → в комнате нажмите **Показать экран** → браузер спросит, что показывать: выберите **окно** с плеером (или вкладку, или весь экран) → при желании включите «Поделиться звуком».

**Жена (с компьютера или телефона):** открывает ссылку из кнопки **Ссылка для жены** (её можно скопировать и отправить), вводит тот же пароль → видит показ и пишет в чат.

**Звук.** Если нужно, чтобы у неё звучали голоса из сериала, при запуске показа включите галочку «Поделиться звуком» (Chrome и Edge, при выборе вкладки или всего экрана). Микрофон включается кнопкой на панели под экраном — по умолчанию он выключен у обоих.

**Микшер.** Кнопка «Громкость» на той же панели открывает микшер: ползунок «Собеседник» делает голос тише или громче (до 300%), «Звук показа» — громкость того, что показывает хозяин. Настройки запоминаются в браузере. Звук идёт через Web Audio, поэтому если после входа в комнату тишина, нажмите появившуюся кнопку «Включить звук» — браузер требует жеста пользователя.

**Микрофон.** Рядом с кнопкой микрофона — стрелка: в панели можно выбрать другое устройство ввода (например, гарнитуру вместо встроенного) и проверить уровень — скажите что-нибудь, полоска должна двигаться. Выбор запоминается в браузере; переключение на лету подхватывается собеседником.

**Экран телефона.** Пока комната открыта, сайт просит браузер не гасить экран (Wake Lock, Chrome/Edge и Safari 16.4+), чтобы телефон не заблокировался сам во время разговора. Ручная блокировка или свёрнутый браузер всё равно прерывают разговор — это ограничение мобильных браузеров, а не сайта.

## Если сервер сигнализации недоступен

Облако PeerJS иногда не отвечает: ошибка «Нет связи с сервером сигнализации». Тогда работает запасной путь — **соединение без сервера**. В лобби под формой входа есть ссылка «Сервер не отвечает? Соединиться вручную».

1. Тот, кто показывает, открывает «Без сервера» → вкладку **Я показываю** → **Создать приглашение** (код готовится пару секунд) → **Скопировать код** и отправить жене любым мессенджером.
2. Она открывает сайт → «Без сервера» → вкладку **Я смотрю** → вставляет код → **Создать ответ** → копирует полученный код и отправляет обратно.
3. Он вставляет ответный код в поле «Шаг 2» → **Подключиться**. Дальше всё как обычно: «Показать экран», чат, микрофон.

Коды — это технические данные соединения в сжатом виде (несколько сотен символов). Их можно передавать в мессенджере: без кода подключиться к комнате нельзя. Обмен нужен один раз за сессию; при обрыве связи процедуру повторяют.

## Как это устроено

- Адрес комнаты — это `SHA-256(название + пароль)`. Без пароля адрес не вычислить, поэтому посторонний не только не войдёт, но и не найдёт комнату. Пароль никуда не отправляется и не хранится.
- Переписка и видео идут **напрямую между браузерами** по WebRTC (шифрование DTLS-SRTP). Сайт не хранит историю: закрыли вкладку — сообщения пропали.
- Через облако PeerJS проходит только «рукопожатие» (обмен техническими данными для соединения), сами сообщения и картинка — нет.
- Хозяин комнаты — узел связи: он принимает гостей, передаёт сообщения чата и отдаёт поток экрана.

## Ограничения (важно знать)

- **Комната живёт, пока открыта вкладка создателя.** Это не сервер, а прямое соединение: закрыли браузер — комната исчезла.
- **Показывать экран можно только с компьютера.** Safari на iPhone и большинство мобильных браузеров не умеют захватывать экран. С телефона можно смотреть и переписываться.
- **Звук системы** передаётся не во всех браузерах: Chrome и Edge — да (галочка «Поделиться звуком»), Firefox — только микрофон.
- **Задержка.** У зрителя картинка и звук идут с сетевой задержкой, поэтому звук у вас двоих не совпадает идеально. Для сериалов это не мешает, для разговоров — слышно эхо, лучше в наушниках.
- **Строгие сети.** Иногда прямое соединение не устанавливается (мобильный оператор, корпоративный Wi-Fi). Тогда нужен TURN-сервер — см. ниже.
- **Пароль защищает от поиска комнаты, но не от перебора.** Ставьте подлиннее, чем 4 символа, если хотите спокойствия.
- История чата не сохраняется и на телефоне не синхронизируется с компьютером — только текущая сессия.
- В комнате до 6 гостей, дальше соединение не откроется.

## Если не соединяется: TURN

STUN-серверы (уже прописаны в `app.js`) помогают в большинстве домашних сетей. Если у кого-то «строгий» NAT, добавьте TURN — он перегоняет трафик через себя.

Бесплатный вариант: зарегистрируйтесь на [metered.ca](https://www.metered.ca/stun-turn) (free plan, 20 ГБ в месяц) и вставьте выданные данные в начало `app.js`:

```js
const ICE_SERVERS = [
  { urls: ['stun:stun.l.google.com:19302', 'stun:stun1.l.google.com:19302'] },
  { urls: 'stun:stun.cloudflare.com:3478' },
  {
    urls: [
      'turn:a.relay.metered.ca:80',
      'turn:a.relay.metered.ca:443',
      'turn:a.relay.metered.ca:443?transport=tcp'
    ],
    username: 'ВАШ_ЛОГИН',
    credential: 'ВАШ_ПАРОЛЬ'
  }
];
```

Такой же блок можно поднять самому на VPS через [coturn](https://github.com/coturn/coturn) — если хочется полной независимости.

## Свой сервер сигнализации (необязательно)

Облако PeerJS бесплатное и обычно работает, но это чужой сервер. Свой поднимается одной командой на любом VPS:

```bash
npm install -g peerjs
peerjs --port 9000 --key peerjs --path /vmeste
```

И в `app.js`:

```js
const PEER_OPTIONS = {
  debug: 1,
  host: 'ваш-домен-или-ip',
  port: 9000,
  path: '/vmeste',
  secure: true,
  key: 'peerjs',
  config: { iceServers: ICE_SERVERS }
};
```

## Локальная проверка перед заливкой

Открывать `index.html` двойным щелчком (`file://`) бесполезно: браузер не даёт доступ к `crypto.subtle` и показу экрана вне HTTPS. Поднимите локальный сервер — `localhost` считается безопасным:

```bash
python -m http.server 8080
```

и откройте `http://localhost:8080`.

## Браузеры

Chrome, Edge, Firefox, Safari 15+ на компьютере. Для просмотра с телефона подойдёт любой современный браузер, включая Safari на iOS и Chrome на Android.
